name: Copy canon rules
description: Founder's standing rules for user-facing strings in Mineral
---

**Rule:** Never invent user-facing copy. Every rendered string must come from a slice spec, seed content, or explicit founder wording. Where copy is unspecified, ask the founder before shipping. Also: never name tabs/navigation (e.g. "origin") inside ritual copy.

**Why:** 2026-08-12 — a drafted "stickiness" line added to the onboarding map hold ("every year you've lived is on this map. it waits in origin.") was rejected as non-canon: the map moment's copy is defined entirely by Slice I v2 (§I1 "you are here." + drag whisper; §I2 practice-screen line). Flagging a draft as a judgment call is not enough — unspecified copy requires asking first.

**How to apply:** When a request implies new visible text ("say something about…"), propose wording in chat via a question and wait for approval, or implement everything else and leave the copy slot empty pending founder wording.

**Detection versus display:** The engine may detect additional patterns, but only findings with founder-approved wording may be rendered. Unworded findings stay hidden and are reported in checkpoint summaries, never given invented or neutral labels.

**Why:** The founder explicitly established this boundary when clarifying Conditions findings: evidence detection does not authorize new language.

**How to apply:** On every engine extension, separately check the evidence gate and approved-copy coverage. Neither alone is sufficient to display a finding.

**Copy must follow computation:** When approved detection and descriptive copy disagree, request corrected copy rather than narrowing the computation to preserve an aesthetic word.

**Why:** The founder explicitly rejected adding a morning restriction to a day-based gap finding merely to retain “morning” in its evidence sentence.

**How to apply:** Preserve the agreed detection rule, flag unsupported claims in the wording, and obtain an accurate founder-approved replacement before rendering.
